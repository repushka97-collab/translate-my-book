# 🔧 ИСПРАВЛЕНИЕ ПРОБЛЕМЫ С ПЕРЕВОДОМ В PDF

## ❌ ПРОБЛЕМА

PDF файл `book_ru.pdf` содержит текст на английском языке, хотя переводы есть в JSON файле.

## 🔍 ПРИЧИНА

1. **PDF_REBUILD метод не работает правильно**:
   - `page.search_for()` не находит текст, потому что текст в PDF разбит на отдельные слова/символы
   - `page.add_redact_annot()` + `page.apply_redactions()` не удаляет текст полностью - только затирает белым, но текст остается в PDF
   - Новый текст вставляется поверх старого, но старый текст все еще виден

2. **HTML→PDF конвертация работает**, но была ошибка переименования файла

## ✅ РЕШЕНИЕ

### Вариант 1: Использовать HTML→PDF (РЕКОМЕНДУЕТСЯ)

HTML→PDF конвертация через Playwright правильно сохраняет переводы:

```bash
# Включить HTML→PDF по умолчанию
$env:HTML_TO_PDF_PLAYWRIGHT="1"
$env:PDF_REBUILD="0"
python run_pipeline.py --source "book.pdf" --mode fast
```

**Преимущества**:
- ✅ Переводы сохраняются правильно
- ✅ Лучшее сохранение форматирования
- ✅ Поддержка кириллицы из коробки

**Недостатки**:
- ⚠️ Может изменить layout (flow layout вместо точного позиционирования)
- ⚠️ Требует Playwright

### Вариант 2: Улучшить PDF_REBUILD

Для точного сохранения позиций можно улучшить PDF_REBUILD:

1. Использовать более агрессивное удаление текста
2. Использовать `page.delete_text()` вместо `redact_annot`
3. Полностью пересоздавать страницы с новым текстом

**Статус**: В разработке

## 🎯 ТЕКУЩЕЕ РЕШЕНИЕ

Исправлена ошибка переименования файла в HTML→PDF конвертации. Теперь HTML→PDF работает по умолчанию и правильно сохраняет переводы.

## 📝 ИНСТРУКЦИЯ

Для получения переведенного PDF:

1. **Использовать HTML→PDF (по умолчанию)**:
   ```bash
   $env:HTML_TO_PDF_PLAYWRIGHT="1"
   python run_pipeline.py --source "book.pdf" --mode fast
   ```

2. **Проверить результат**:
   ```bash
   python -c "import fitz; doc = fitz.open('output/.../book_ru.pdf'); print(doc[0].get_text()[:500])"
   ```

3. **Если нужен точный layout**, использовать `PDF_REBUILD=1` (но он требует доработки)
