# Архитектура EWB Core Engine

## Обзор

EWB Core Engine — это пайплайн для перевода PDF книг с английского на русский язык с сохранением структуры и верстки.

## Архитектура пайплайна

```
PDF → Ingest → Normalize → Translate → QA → Layout → Export → Library
```

### 1. Ingest (Извлечение)
- **Модуль**: `core_engine/ingest/`
- **Функции**: 
  - Извлечение текстовых блоков из PDF
  - Извлечение изображений
  - Извлечение метаданных (шрифты, размеры)
- **Выход**: `BookDocument` с блоками и изображениями

### 2. Normalize (Нормализация)
- **Модуль**: `core_engine/normalize/`
- **Функции**:
  - Очистка текста от артефактов PDF
  - Извлечение protected tokens (термины, URL, DOI)
  - Детекция заголовков
  - Детекция структуры глав (Part/Chapter/Section)
- **Выход**: Нормализованные блоки с метаданными

### 3. Translate (Перевод)
- **Модуль**: `core_engine/translate/`
- **Backends**:
  - `NLLBBackend`: базовый перевод через NLLB (600M/1.3B)
  - `HybridBackend`: NLLB baseline + LLM refine
  - `CachedBackend`: обертка с кэшированием
- **Post-processing**:
  - `quality_pass`: очистка артефактов
  - `editor_pass`: исправление ошибок
  - `term_normalizer`: нормализация терминов
- **Выход**: Переведенные блоки

### 4. QA (Контроль качества)
- **Модуль**: `core_engine/qa/`
- **Проверки**:
  - Пустые переводы
  - Несоответствие длины
  - Смешение алфавитов
  - Повторяющиеся токены
  - Подозрительные символы
- **Выход**: QA отчет с проблемами

### 5. Layout (Верстка)
- **Модуль**: `core_engine/layout/`
- **Функции**:
  - Построение layout модели
  - Двухколоночная верстка
  - Детекция таблиц
  - Детекция сносок и формул
  - Построение paragraph stream
- **Выход**: Структурированный поток параграфов

### 6. Export (Экспорт)
- **Модуль**: `core_engine/export/`
- **Форматы**:
  - DOCX: финальный документ с версткой
  - JSON: промежуточные данные для отладки
- **Выход**: `book_ru.docx` и JSON файлы

### 7. Library (Библиотека)
- **Модуль**: `core_engine/library/`
- **Функции**:
  - Регистрация книг
  - Сохранение манифестов
  - Управление структурными слоями
- **Выход**: Запись в `library/<book_id>/`

## Ключевые компоненты

### Translation Backends

#### NLLBBackend
- Быстрый перевод через NLLB модели
- Поддержка GPU/CPU
- Batch processing для ускорения

#### HybridBackend
- NLLB для базового перевода всех блоков
- LLM (Ollama) для улучшения важных блоков:
  - Заголовки (heading1, heading2)
  - Подписи (caption)
  - Длинные блоки (>200 символов)

#### CachedBackend
- Кэширование переводов по хешу текста
- Пропуск уже переведенных блоков
- Ускорение повторных запусков

### Layout Engine

#### Двухколоночная верстка
- Автоматическое определение колонок
- Чередование блоков по y-позиции
- Сохранение правильного порядка чтения

#### Детекция структуры
- Part/Chapter/Section через паттерны
- Сохранение иерархии в metadata
- Использование для улучшения верстки

## Конфигурация

### configs/llm.yaml
- Профили переводов (dev, fast, full, hybrid)
- Параметры моделей (batch_size, max_length)
- Настройки кэширования

### Производительность
- RTX 5080: batch_size=32, оптимизированная генерация
- CPU: batch_size=4, более медленная обработка
- Кэширование: автоматическое для режима `fast`

## Troubleshooting

### Проблемы с GPU
- Проверьте CUDA: `torch.cuda.is_available()`
- Если нет CUDA, используйте `--mode full`
- При OOM ошибках уменьшите `batch_size`

### Проблемы с качеством
- Используйте режим `hybrid` для лучшего качества
- Проверьте QA отчет в `output/<book_id>/qa_report.json`
- Убедитесь что Ollama запущена для hybrid режима

### Проблемы с версткой
- Проверьте `paragraph_stream.json` для отладки
- Убедитесь что PDF содержит структурированный текст
- Изображения могут не извлекаться из некоторых PDF
